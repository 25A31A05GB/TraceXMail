## 1. Executive Definition: Composite Threat Index vs. Probability

> **CRITICAL SCIENTIFIC DISTINCTION:**  
> The **Threat Score** (0–100) produced by TraceXMail is a **deterministic, multi-layer composite heuristic risk index**, **NOT** an ML probability or statistical confidence value.

- **ML Probability ($P(y = c \mid \mathbf{x}) \in [0.00, 1.00]$):** The statistical posterior likelihood generated by the Cosine Centroid / Softmax inference engine evaluating text and header token frequencies.
- **Model Confidence ($\Delta P \in [0.00, 1.00]$):** The margin between the top-1 and top-2 predicted class probabilities.
- **Composite Threat Score ($\text{Score} \in [0, 100]$):** A cumulative structural rating derived from five independent forensic verification layers (Authentication, Domain Reputational Risk, Infrastructure Routing, ML Posterior Weight, and Behavioral Header Heuristics).

### Why Threat Score Can Be High When ML Confidence Is Low
An attacker sending an email containing completely benign or novel wording (resulting in low ML probability) can still achieve a critical Threat Score (e.g., 85/100) because:
1. Cryptographic authentication failed (SPF/DKIM/DMARC hard fails: +25 pts)
2. Domain is an unaligned lookalike registered 2 days ago (+25 pts)
3. Originating MTA routed through a known Tor exit node or bulletproof ASN (+20 pts)
4. Reply-To header diverts to an unrelated personal webmail mailbox (+10 pts)

Conversely, a legitimate security newsletter with frequent usage of words like "phishing", "malware", and "credentials" will trigger elevated NLP tokens, but because cryptographic authentication (SPF/DKIM/DMARC) passes cleanly and sending infrastructure is legitimate, its composite Threat Score remains low (CLEAN / LOW risk).

## 2. Threat Score Formula & Weight Breakdown

The composite Threat Score is computed additively across five distinct forensic tiers, capped at a maximum of 100 points:

$$\text{Threat Score} = \min\left(100, S_{\text{auth}} + S_{\text{domain}} + S_{\text{infra}} + S_{\text{ml}} + S_{\text{heuristics}}\right)$$

```
+-----------------------------------------------------------------------------+
|                     TRACEXMAIL THREAT SCORE (0 - 100)                       |
+-----------------------------------------------------------------------------+
| 1. Cryptographic Authentication (SPF / DKIM / DMARC)         : Max 25 pts   |
| 2. Domain Intelligence, Typosquatting & Brand Alignment      : Max 25 pts   |
| 3. Network Infrastructure, Routing & Anonymization           : Max 20 pts   |
| 4. Content ML Classification & Natural Language Model        : Max 20 pts   |
| 5. Identity Spoofing & Reply Redirection Heuristics          : Max 10 pts   |
+-----------------------------------------------------------------------------+
| TOTAL MAXIMUM SCORE                                          : 100 pts      |
+-----------------------------------------------------------------------------+
```

## 3. Detailed Component Weight Breakdown

### Tier 1: Cryptographic Authentication ($S_{\text{auth}}$ — Maximum 25 Points)
Evaluates RFC 7208 (SPF), RFC 6376 (DKIM), and RFC 7489 (DMARC) alignment:
- **DMARC Hardfail / Reject Policy Violated:** `+25 pts`  
  *The domain owner explicitly publishes a `p=reject` policy and the inbound message failed both SPF and DKIM alignment.*
- **DMARC Quarantine / Softfail:** `+15 pts`
- **DKIM Signature Invalid / Cryptographic Hash Mismatch:** `+15 pts`  
  *Header signature fails RSA/Ed25519 verification, indicating tampering in transit or forged headers.*
- **SPF Fail (`-all`):** `+15 pts`  
  *Sending MTA IP is not authorized in sender domain's SPF TXT record.*
- **SPF Softfail (`~all`):** `+8 pts`
- **Missing All Authentication Records:** `+10 pts`

### Tier 2: Domain Intelligence & Brand Alignment ($S_{\text{domain}}$ — Maximum 25 Points)
Evaluates domain registration, typosquatting, and brand impersonation:
- **Display-Name Brand Spoofing (Brand Mismatch):** `+25 pts`  
  *Display name claims a recognized brand (e.g. "DocuSign Services" or "Microsoft 365"), but sending domain is completely unauthorized (e.g. `docusign-envelope-sign.net`).*
- **Algorithmic Typosquatting / Lookalike Domain:** `+20 pts`  
  *Domain Levenshtein distance $\le 2$ or contains hyphenated target brand (e.g. `chase-banking-security.com`).*
- **Newly Registered Domain (< 14 days old):** `+15 pts`
- **High Entropy / DGA Domain Name:** `+12 pts`

### Tier 3: Network Infrastructure & Routing ($S_{\text{infra}}$ — Maximum 20 Points)
Evaluates network hops, relay trust boundaries, and anonymizing infrastructure:
- **Originating Ingress Hop is Known Tor Exit Node:** `+20 pts`  
  *Ingress relay IP matches active Tor Directory consensus or public exit list.*
- **Ingress Relay in Known High-Abuse / Bulletproof ASN:** `+15 pts`
- **Relay Hop Geolocation / Timezone Impossibility Anomaly:** `+10 pts`  
  *Client submission timestamp and originating MTA timezone differ by > 8 hours without corporate relay presence.*
- **Missing or Forged Received Headers (Header Traversal Anomaly):** `+10 pts`

### Tier 4: Content ML Classification ($S_{\text{ml}}$ — Maximum 20 Points)
Transforms the supervised ML classifier posterior into an evidence contribution:
- **$P(\text{Phishing}) \ge 0.80$ OR $P(\text{Fraud-related}) \ge 0.80$:** `+20 pts`
- **$P(\text{Phishing}) \ge 0.50$ OR $P(\text{Fraud-related}) \ge 0.50$:** `+12 pts`
- **$P(\text{Impersonated}) \ge 0.60$:** `+15 pts`
- **$P(\text{Suspicious}) \ge 0.60$:** `+8 pts`
- **$P(\text{Legitimate}) \ge 0.85$:** `-10 pts` *(Mitigating bonus for authentic engineering/developer mail)*

### Tier 5: Behavioral & Identity Heuristics ($S_{\text{heuristics}}$ — Maximum 10 Points)
Evaluates header diverters and social engineering patterns:
- **Reply-To Domain Mismatch (`Reply-To` $\neq$ `From` Domain):** `+10 pts`  
  *Replies are diverted away from the spoofed sender to an adversary-controlled external mailbox.*
- **Return-Path Bounce Address Mismatch:** `+6 pts`
- **High-Pressure BEC Urgency / Wire Transfer Keywords:** `+8 pts`

## 4. Institutional Severity Thresholds

TraceXMail maps the final Threat Score (0–100) to standardized SOC operational action levels:

| Threat Score Range | Severity Rating | SOC Operational Action |
| :--- | :--- | :--- |
| **80 – 100** | **CRITICAL EXPOSURE** | Automated quarantine; isolate compromised endpoint credentials; revoke active session tokens; initiate security incident ticket. |
| **60 – 79** | **HIGH RISK** | Quarantine inbound email; issue warning banner if released; alert SOC security analyst for manual review. |
| **35 – 59** | **MEDIUM RISK** | Inbound warning banner inserted; external sender tags applied; links sandboxed via safe-browsing proxy. |
| **15 – 34** | **LOW RISK** | Deliver with standard external sender indicator; log telemetry in SIEM. |
| **0 – 14** | **CLEAN / VERIFIED** | Deliver to recipient inbox without friction; cryptographic checks fully satisfied. |
